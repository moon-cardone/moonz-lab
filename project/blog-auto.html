편집창 복구·저장 확인

다듬는 중

입력이 멈춘 편집창은 화면 크기와 저장 상태부터 확인하도록 복구 절차를 보완했습니다. 내용은 읽히지만 화면이 0×0으로 잡힌 경우가 있어, 로그인 오류로 단정하지 않고 원고와 이미지를 보존했습니다.

사용자가 새로 연 창에 준비된 원고를 복원하고, 실제 임시저장 목록에서 다시 불러와 제목·본문·이미지와 문단 간격을 대조했습니다. 이전 창의 자동저장 표시만으로 서버에 저장됐다고 판단하지 않도록 했습니다.

새 창에서 저장과 재개방을 확인한 뒤 이전 창을 정리했습니다. 원고를 다시 만들거나 이미 끝난 생성 단계를 반복하지는 않았습니다. 화면이 0×0이 되는 브라우저 내부 원인은 아직 확인하지 못했고, 영구적인 장애 해결로 보지는 않습니다.

등록 전 글 유형 확인

다듬는 중

지원하지 않는 글 유형으로 등록한 뒤 준비 단계에서 막히는 일을 줄이려고, 등록 전에 기존 유형 검사 함수를 먼저 호출하는 절차를 적용했습니다.

이번 등록 요청 두 건에서 유형 검사와 실제 준비 단계의 정상 통과를 확인했습니다. 앞서 반려된 글감은 실패 기록을 남겨 두고 같은 항목의 유형만 고쳐 준비를 다시 진행했습니다. 같은 글감을 새로 등록하지는 않았습니다.

지원 유형이나 검사 엔진을 새로 추가한 작업은 아닙니다. 기존 검사를 먼저 쓰도록 순서를 바꿨습니다. 유형 검사를 통과한 원고도 본문 검수에서 보류될 수 있어, 검수와 실제 발행 확인은 별도로 유지합니다.

제목·사진 설명 입력 보완

다듬는 중

제목이나 사진 설명이 본문에 들어가는 경우가 있어, 입력 전에 선택된 칸을 확인하도록 편집 순서를 바꿨습니다. 붙여 넣은 뒤에도 실제 제목란과 사진 설명란의 내용을 각각 대조합니다.

여러 사진의 설명을 빠르게 이어 붙이는 대신, 현재 사진의 설명칸이 선택된 것을 확인하고 한 장씩 처리합니다. 제목은 남아 있는 한글 조합을 끝낸 뒤 교체하고, 같은 문장이 본문에 있다는 이유만으로 제목 입력 성공으로 보지 않게 했습니다.

저장한 글을 다시 열어 제목·본문·사진 설명과 문단 간격이 원고와 일치하는 것을 확인했습니다. 현재 편집 화면에서 확인한 결과이므로, 화면 구조가 바뀌거나 다른 브라우저를 쓰면 입력 위치를 다시 확인해야 합니다.

정리됨

작성·윤문 단계에서 간격을 맞춘 뒤, 실제 웹 편집기에서도 문단 순서와 빈 줄 위치를 대조했습니다. 저장 후 다시 열어 본문과 간격이 유지되는 것을 확인했습니다.

이미 예약하거나 공개한 글은 소급 수정하지 않았습니다. 이번 확인은 웹 편집기의 저장 결과까지이며, 모든 기기에서의 표시를 검사한 것은 아닙니다.

본문 기준 중복 검사

정리됨

키워드가 겹친다는 이유만으로 다른 내용의 글까지 막히지 않도록, 주제 겹침과 동일 본문을 구분하게 바꿨습니다. 비슷한 주제는 참고 표시만 남기고, 같은 원고의 재등록은 저장 전에 차단합니다.

보관된 완료 원고와 대기 초안을 대조합니다. 제목·공백·이미지 표시만 바꾼 같은 본문은 이미지 생성과 외부 저장 전에 멈추며, 진행 중인 초안을 덮어쓰지 않는 보호도 유지했습니다.

모의 검사에서 비슷한 주제의 다른 본문은 통과하고, 같은 본문은 차단되는 것을 확인했습니다. 비교 범위는 로컬에 보관된 네이버 원고입니다. 공개된 모든 글을 전수 검사하지는 않으며, 의미는 같고 표현만 다른 글은 별도 본문 검수가 필요합니다.

모델명 태그 입력 보정

정리됨

모델명에 들어간 하이픈 때문에 태그 등록이 막혔습니다. 본문의 정확한 모델명은 그대로 두고, 태그에만 하이픈을 뺀 표기를 사용했습니다.

제목·본문·이미지는 바꾸지 않고 태그 변경 부분만 다시 검수했습니다. 실제 편집기에 등록된 태그와 저장한 목록을 대조하고, 저장 후 다시 열어 내용이 유지되는 것을 확인했습니다.

모델명 태그는 입력 가능한 표기로 준비하고 실제 등록 결과를 확인하도록 작업 지침에도 남겼습니다. 본문까지 일괄 치환하거나 기존 검수 결과를 처음부터 다시 만들지는 않았습니다.

실패 원고 보존·이어가기

다듬는 중

한 원고에서 막히면 뒤의 작업까지 멈추던 흐름을 바꿨습니다. 실패한 원고와 오류·재개 단계를 따로 보존하고 다음 미처리 작업으로 넘어갑니다.

남은 작업을 처리한 뒤 보류한 위치부터 다시 시도하며, 실패한 작업을 완료로 집계하지 않습니다. 등록 여부가 불명확한 작업은 다시 제출하지 않고 확인 대기로 남깁니다.

기존 원고와 이전 기록, 다른 대기 작업이 보존되는지 대조하고 다음 작업으로 넘기는 상태를 확인했습니다. 공통 실행 환경의 오류까지 해결한 것은 아니며, 기존 작성·검수 기준도 그대로 유지합니다.

글감 중복 등록 방지

정리됨

글감 등록 요청의 응답이 끊겼을 때 같은 글감이 다시 추가되지 않도록, 등록 요청은 자동으로 재전송하지 않게 바꿨습니다. 목록 조회와 같은 항목의 상태 갱신은 기존 재시도를 유지합니다.

서버가 먼저 저장한 뒤 응답만 유실되는 상황을 모의 검사했습니다. 이때 추가 요청은 한 번만 보내고, 조회·갱신 재시도와 정상 등록 응답은 유지되는 것을 확인했습니다.

응답이 없다고 등록 실패로 단정할 수는 없습니다. 이런 경우에는 실제 대기 목록을 확인한 뒤 재처리해야 합니다. 서버 쪽 동작이나 과거 중복 발생 원인까지 확인한 것은 아닙니다.

정리됨

작업 뒤에는 확인된 변경만 지침에 반영하고 변경 이유를 남기도록 기존 자동화에 점검 절차를 더했습니다. 이전 원고와 예약·공개 기록은 그대로 두고, 바뀐 작성 기준은 다음 작업부터 적용합니다.

보관 파일을 원본과 대조하고 문서 링크와 현재 도구 연결을 점검했습니다. 이번에는 지침과 보관 구조를 정리했으며 새 발행 기능은 추가하지 않았습니다. 보관한 확장을 다시 쓰려면 별도 동작 확인이 필요합니다.
