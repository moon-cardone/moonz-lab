# moonz.lab

혼자 만들고, 혼자 굴립니다.

https://moon-cardone.github.io/moonz-lab/

**여기엔 프로젝트 업데이트를 올립니다.** 공부한 것·기술 메모는 옵시디언에.

## 글 하나 올리기

**1. 파일 만들기** — `content/log/` 에 `.md` 파일을 하나 만든다.
`_template.md.txt` 를 복사해서 쓰면 편하다.

```markdown
---
date: 2026-08-06
title: 오늘 고친 것
tags: pushdown
status: 러프
---

한 줄만 써도 된다.
```

**2. 올리기** — 둘 중 아무거나.

- `publish.bat` 더블클릭
- 클로드에게 **"발행해줘"**

2~3분 뒤 사이트에 반영된다.

날짜나 제목을 빠뜨리면 **올라가지 않고 멈춘다.** 어느 파일이 문제인지 알려주니 고치고 다시 누르면 된다.

## 일일 기록

Codex의 예약 작업이 매일 한국 시간 자정에 직접 만든 앱과 자동화의 새 작업을 확인합니다.
공부 메모와 민감한 운영 정보는 제외하고, 새 작업이 없는 날은 글을 만들지 않습니다.
이 예약은 GitHub Actions 자체의 정기 실행이 아니라 Codex의 로컬 실행 환경을 사용합니다.

기존 글은 `date_display: year`로 `2026년 · 작업 정리`처럼 보입니다. 내부 `date`는 삭제하지 않습니다.
새 일일 업데이트에는 이 항목을 생략해 작업 날짜를 표시합니다. 자정에는 전날의 확인된 작업을 기록합니다.
늦게 정리한 회고는 작성일을 `date`에 넣고 `date_display: year`로 표시합니다.

대표 작업 카드는 유지하고, 나머지는 제목·짧은 설명만 있는 목록으로 표시합니다. 목록을 누르면 상태·도구와 작업 기록을 볼 수 있습니다. 이미지는 넣지 않으며 파스텔 색감은 유지합니다.

목록은 PC 3열·태블릿 2열·모바일 1열입니다. 프로젝트 앞머리의 `category`에 `자동화 도구`(민트), `앱·게임`(보라), `웹사이트`(살구)를 적습니다. 생략한 기존 파일은 중립색으로 표시하고, 잘못된 분류값은 발행을 중단합니다.

대표 작업 세 개에는 `featured: true`와 `problem`, `approach`, `result`를 적습니다.
각각 출발점·만든 방식·현재 상태이며, 하나라도 빠지면 발행을 멈춥니다. 나머지 작업은 기존 순서를 유지합니다.
첫 화면의 일지는 첫 문단만 표시하고 제목을 누르면 기존 프로젝트 페이지에서 전체 글을 읽습니다.

## 쓸 수 있는 값

`date` 와 `title` 은 반드시 있어야 하고, 나머지는 없어도 된다.

| 항목 | 쓰는 것 |
|---|---|
| `date` | `2026-08-06` 형식만 |
| `title` | 제목 |
| `tags` | 쉼표로 여러 개 |
| `status` | `러프` · `다듬는 중` · `정리됨` |
| `date_display` | 생략하면 날짜 표시, `year`면 연도와 작업 정리만 표시 |

프로젝트는 `status` 가 `운영 중` · `만드는 중` · `멈춤` 이다.

## 프로젝트별 일지

카드를 누르면 그 프로젝트 일지만 모아둔 페이지로 간다.

일지 `tags` 에 프로젝트 이름을 그대로 적으면 그 페이지에 들어간다.

```
쓰레드 자동 포스팅 · 블로그 자동 포스팅 · 한 줄 육아
작업 기록 사이트 · pushdown · 인스타툰 공장
```

띄어쓰기가 헷갈리면 `project: 한 줄 육아` 를 써도 된다.
